\vspace{-1.2cm}
\begin{center}\small
\begin{tcolorbox}[colback=gray!5,colframe=gray!50,width=0.9\textwidth]
This guide describes \emph{in practice} how to build and use the assimilation layer
(folder \file{assim/}, executable \code{sw2d\_enzyme}) added to the SW2D solver. It
covers: building with Enzyme, the sequence of executables, the \file{input.solv}
parameters and how to tune them, plus the Python scripts used for preparation and
diagnostics. The native SW2D solver is left untouched; the whole AD layer lives in
\file{assim/}.
\end{tcolorbox}
\end{center}

% =====================================================================
\section{Building with Enzyme}
% =====================================================================

\paragraph{Prerequisites.}
\begin{itemize}
  \item native SW2D (the \file{src/} tree, unmodified);
  \item \textbf{clang-18} and \textbf{lld-18} (\code{sudo apt install clang-18 lld-18});
  \item the \textbf{Enzyme} plugin for LLVM~18 (files \file{ClangEnzyme-18.so} and
        \file{LLDEnzyme-18.so});
  \item \textbf{Eigen~3} (\code{sudo apt install libeigen3-dev});
  \item the optimisation libraries \file{LBFGSpp} and \file{psqn} (header-only, shipped
        in \file{assim/external/}).
\end{itemize}

\paragraph{Commands.} From the root of the repository (the \file{assim/} folder sits next
to \file{src/}):
\begin{lstlisting}[language=bash]
# folder holding ClangEnzyme-18.so and LLDEnzyme-18.so :
export ENZYME_PLUGIN_DIR=$HOME/Enzyme/build/Enzyme

cmake -S assim -B build_assim -DENABLE_ENZYME=ON -DCMAKE_CXX_COMPILER=clang++-18
cmake --build build_assim -j
\end{lstlisting}
\begin{sloppypar}
\noindent Without \code{-DENABLE\_ENZYME=ON} the target is \emph{not} built (Enzyme is
required to link \code{\_\_enzyme\_autodiff}). The resulting executable is
\file{build\_assim/sw2d\_enzyme}.
\end{sloppypar}

\begin{tcolorbox}[colback=orange!5,colframe=orange!55,title=\small Why clang+lld+LTO?]
\small Enzyme differentiates the \emph{merged LLVM IR}: compilation is done with
\code{-flto} (bitcode, without vectorisation or unrolling), and it is \code{lld-18} that
loads the Enzyme plugin at link time to generate the adjoint code. This is why \code{gcc}
is not suitable for this target.
\end{tcolorbox}

% =====================================================================
\section{Structure of a case}
% =====================================================================

A case is a standard SW2D configuration folder, supplemented with assimilation-specific
files in its \file{input/} subfolder:
\begin{center}\small
\begin{tabular}{@{}ll@{}}
\toprule
\textbf{File} & \textbf{Role} \\
\midrule
\file{input.solv}                    & all parameters (simulation + assimilation) \\
\file{geometry.sw2d}, mesh           & geometry of the case (as in native SW2D) \\
\file{SP\_cell\_porosity\_map.txt}   & \emph{truth} porosity map (twin experiment) \\
\file{phi\_init\_ones.txt}           & \emph{background} porosity map (starting point, e.g.\ $\varphi\equiv1$) \\
\file{reference/}                    & reference observations (generated by \code{gen-ref-e}) \\
\file{descent/}                      & (created at run time) minimisation monitoring \\
\bottomrule
\end{tabular}
\end{center}

% =====================================================================
\section{The executables (modes) and the order to follow}
% =====================================================================

Everything goes through a single executable: \code{sw2d\_enzyme <case\_folder> <mode>}.
The first argument is the case folder, the second one is the \emph{mode}.
\textbf{Recommended order for a new configuration}:

\begin{enumerate}
  \item \textbf{\code{gen-ref-e}} — generates the \emph{reference observations} with the
  differentiable forward model (\file{\_E}). In a twin experiment this guarantees
  $J(\varphi_{\text{true}})\approx 0$. \emph{To be redone whenever the truth or the mesh
  changes.}
\begin{lstlisting}[language=bash]
sw2d_enzyme my_case gen-ref-e
\end{lstlisting}

  \item \textbf{\code{taylor}} — \emph{validates the gradient} with a Taylor test (the
  Enzyme gradient must match finite differences, ratio $\to 1$). \textbf{To be run for
  every new configuration} before assimilating: if the test fails, minimisation is
  meaningless.
\begin{lstlisting}[language=bash]
sw2d_enzyme my_case taylor
\end{lstlisting}

  \item \textbf{\code{minimize}} — runs the \emph{assimilation} proper: minimises the cost
  function and writes the reconstructed map to \file{optimized\_porosity.txt} (+
  monitoring in \file{descent/}).
\begin{lstlisting}[language=bash]
sw2d_enzyme my_case minimize
\end{lstlisting}
\end{enumerate}

\noindent \emph{Other modes} (secondary): \code{forward} (a single \file{\_E} direct
simulation) and \code{gen-ref} (references through the classical native engine).

% =====================================================================
\section{Assimilation parameters in \file{input.solv}}
% =====================================================================

On top of the usual SW2D parameters, the following keys are available (default values in
parentheses).

\paragraph{Maps and cost function.}
\begin{center}\small
\begin{tabular}{@{}lp{10.3cm}@{}}
\toprule
\code{porosity\_ref\_map}     & \emph{truth} porosity map (target of \code{gen-ref-e} and of the monitoring). \\
\code{porosity\_ebauche\_map} & \emph{background} map = starting point of the reconstruction. \\
\code{h\_weight}, \code{q\_weight} (1) & weights of the depth $h$ / discharge $\mathbf q$ terms in $J$ (scalar or map). \\
\code{cost\_normalize} (false) & divides $J$ by the number of observations (window-invariant). \\
\code{alpha\_reg} (0) & Tikhonov regularisation towards the background. \\
\bottomrule
\end{tabular}
\end{center}

\paragraph{Optimiser.}
\begin{center}\small
\begin{tabular}{@{}lp{9.2cm}@{}}
\toprule
\code{minimize\_algo} (\code{bfgs}) & \code{lbfgsb} (recommended, bounded) / \code{adam} / \code{bfgs}. \\
\code{max\_it} & number of optimiser iterations (\emph{per window} with QSVA). \\
\code{phi\_transform} (\code{none}) & change of variable $\varphi\!\leftrightarrow\!m$ (\code{none} recommended with \code{lbfgsb}). \\
\code{phi\_lower\_bound}, \code{phi\_upper\_bound} (0, 1) & bounds of the L-BFGS-B box. \\
\code{adam\_step\_size} (0.05) & Adam step size (if \code{minimize\_algo=adam}). \\
\bottomrule
\end{tabular}
\end{center}

\paragraph{Assimilation window, tiling and checkpoints.}
\begin{center}\small
\begin{tabular}{@{}lp{10.3cm}@{}}
\toprule
\code{t\_state\_assimilation} & start of the observation window (observations in $[t_{\text{state}}, t_{\max}]$ are used). \\
\code{t\_max} & end of the window (end of simulation). \\
\code{windowed\_assimilation} (false) & enables the window + the tiling of the adjoint. \\
\code{n\_assimilation\_windows} (1) & number of \emph{tiles} (adjoint bounded tile by tile). \\
\code{checkpoint\_stride} (30) & number of time steps per checkpoint segment. \\
\code{dt\_map\_ad} & observation rate within the window. \\
\bottomrule
\end{tabular}
\end{center}

\paragraph{QSVA (growing window).}
\begin{center}\small
\begin{tabular}{@{}lp{10.3cm}@{}}
\toprule
\code{qsva\_enabled} (false) & enables quasi-static minimisation with a growing window. \\
\code{qsva\_delta\_tau} & increment $\delta\tau$ (s) by which the window grows at each step. \\
\bottomrule
\end{tabular}
\end{center}

% =====================================================================
\section{How to choose the parameters (practical aspects)}
% =====================================================================

\begin{description}
  \item[\code{n\_assimilation\_windows} (tiles).] \textbf{More} tiles $\Rightarrow$
  a \emph{more stable} adjoint (bounded backward growth), at the price of a slight
  overhead. \textbf{Too few} $\Rightarrow$ the adjoint \emph{blows up} on long windows,
  the gradient is truncated and the reconstruction fails. \emph{In practice}: increase
  until the adjoint no longer reports a blow-up (e.g.\ 48 on the Toce case). $1$ = no
  tiling.

  \item[\code{checkpoint\_stride}.] \textbf{Smaller} $\Rightarrow$ less RAM per Enzyme
  call (shorter tape) and finer tiling, but more stored checkpoints and slightly slower.
  \textbf{Larger} $\Rightarrow$ faster if it fits in memory, but a risk of saturation
  (OOM). \emph{In practice}: leave it around $\sim\!30$; \emph{reduce} it if memory runs
  short.

  \item[Window {\normalfont(\code{t\_state\_assimilation}, \code{t\_max})}.] Cover the
  \emph{informative period} (the wave\,--\,structure interaction). Starting too early
  (before the wave arrives) or extending a non-informative tail brings no signal and
  \emph{weakens} the adjoint. \emph{In practice}: a \emph{short window centred} on the
  event often beats the full window; the script \file{identifiability\_plot.py}
  (§\ref{sec:python}) returns this window directly.

  \item[\code{qsva\_delta\_tau} (QSVA).] \textbf{Smaller} $\Rightarrow$ more windows,
  better \emph{continuity} (the absolute minimum is tracked, local minima are avoided),
  but more computation. \textbf{Too large} $\Rightarrow$ the process "jumps" and QSVA may
  fall back into a local minimum (losing its benefit). \emph{In practice}: take the
  \emph{largest} $\delta\tau$ that preserves quality (2\,--\,4~s on the Toce).

  \item[\code{minimize\_algo}.] \code{lbfgsb} = robust and deterministic (recommended
  default, bounds $\varphi\in[0,1]$); \code{adam} = first order, reaches $\varphi=0$
  exactly (useful when the parameter must vanish); \code{bfgs} = dense quasi-Newton.

  \item[\code{h\_weight} / \code{q\_weight}.] Keep $h$ \emph{and} $\mathbf q$ (the
  discharge carries the information about the deflection caused by the structure); a
  uniform weight is a good starting point, and a \emph{data-driven} weighting is provided
  by \file{make\_cost\_weight\_map.py} (§\ref{sec:python}) if $J$ should be focused on the
  area of interest.
\end{description}

% =====================================================================
\section{Python scripts (\file{utils\_assim/python})}
\label{sec:python}
% =====================================================================

The Python scripts are \emph{never} part of the computation: they \emph{prepare} inputs
(weight maps) and \emph{diagnose} outputs (convergence, gradient, reconstructed maps).
They only depend on \code{numpy} and \code{matplotlib}, and are run from the case folder.

\paragraph{Preparation and configuration.}
\begin{center}\small
\begin{tabular}{@{}lp{9.6cm}@{}}
\toprule
\textbf{Script} & \textbf{Role} \\
\midrule
\file{make\_cost\_weight\_map.py}    & builds the weighting maps \file{w\_h.csv} / \file{w\_q.csv} from the discrepancy between \emph{background} and \emph{truth} taken at the \emph{same instant} (two \file{ResultHydro} files). Weights are large where the two diverge, i.e.\ in the area influenced by the structure: $J$ then "looks at" the structure without assuming its geometry. To be plugged in through \code{h\_weight} / \code{q\_weight}. \\
\file{personal\_path\_template.py}   & template to be renamed \file{personal\_path.py}: defines the (OS-dependent) paths to the SW2D executables used by the other scripts. \\
\bottomrule
\end{tabular}
\end{center}

\paragraph{Time diagnostics (\file{plot/}).}
\begin{center}\small
\begin{tabular}{@{}lp{9.6cm}@{}}
\toprule
\textbf{Script} & \textbf{Role} \\
\midrule
\file{identifiability\_plot.py}      & \emph{temporal identifiability} curve: the innovation $|$truth $-$ background$|$ aggregated over the cells of the structure, as a function of time. It returns the interval where the innovation exceeds a fraction of the peak: this is the window to copy into \code{t\_state\_assimilation} / \code{t\_max}. \\
\file{plot\_descent.py}              & convergence of the minimisation from \file{descent/descent\_log.csv}, in 3~panels: $J$ (log scale), squared error against the truth map (\code{sse\_phi\_ref}), and \% of descent relative to $J_{\text{init}}$. \\
\file{plot-dambreak.py}              & standalone didactic figure (1D case with 100 cells): initial water-depth conditions and the associated porosity map. No computed result required. \\
\bottomrule
\end{tabular}
\end{center}

\paragraph{Spatial diagnostics on the mesh (\file{plot/mesh\_plot/}).} All of them colour
the polygons of a \file{.2dm} mesh \emph{cell by cell}.
\begin{center}\small
\begin{tabular}{@{}lp{9.6cm}@{}}
\toprule
\textbf{Script} & \textbf{Role} \\
\midrule
\file{mesh\_all.py}                  & quick display of the bare mesh (wireframe), to check the geometry. \\
\file{mesh\_all\_phi.py}             & generic plot of a per-cell field on the mesh: \code{phi}, \code{grad}, \code{grad\_signe}, \code{cost}, \code{h}, \code{q}, \code{z}, \code{zb}. This is the tool to use to visualise a reconstructed map (\file{optimized\_porosity.txt}). \\
\file{plot\_gradient\_map.py}        & map of the gradient $\partial J/\partial\varphi$ (\file{gradient\_porosity.csv}). It exhibits the \emph{null space}: the gradient is non-zero only on the \emph{observable} cells (front, flow axes), and $\approx 0$ elsewhere. \\
\file{mesh\_cost\_plot.py}           & per-cell misfit between a reference \file{ResultHydro} and a computed \file{ResultHydro} at the same instant: shows \emph{where} the cost is paid. \\
\file{compare\_h\_phimaps.py}        & comparison of two water-depth fields $h$ (same mesh, same instant, only the porosity map changes) in 4~panels: $h_1$, $h_2$, absolute $\Delta h$ (m) and relative $\Delta h$ (\%), dry cells being masked. \\
\bottomrule
\end{tabular}
\end{center}

\paragraph{Typical sequence.}
\begin{lstlisting}[language=bash]
# 0. background (phi=1) + truth : two sets of ResultHydro at the same instants
sw2d_enzyme my_case gen-ref-e      # -> reference/
sw2d_enzyme my_case forward        # -> output/

# 1. choose the assimilation window (identifiability peak)
python3 utils_assim/python/plot/identifiability_plot.py \
        --ref-dir my_case/reference --eb-dir my_case/output \
        --dam my_case/input/SP_cell_porosity_map.txt

# 2. (optional) weight the cost over the area of interest
python3 utils_assim/python/make_cost_weight_map.py \
        my_case/output/ResultHydro_<t>.txt my_case/reference/ResultHydro_<t>.txt

# 3. assimilate, then diagnose
sw2d_enzyme my_case minimize
python3 utils_assim/python/plot/plot_descent.py my_case/descent/descent_log.csv
python3 utils_assim/python/plot/mesh_plot/mesh_all_phi.py \
        my_case/primary_files/mesh.2dm phi my_case/optimized_porosity.txt
\end{lstlisting}

\begin{tcolorbox}[colback=orange!5,colframe=orange!55,title=\small Two diagnostic reflexes]
\small If the minimisation stalls, look \emph{in this order} at: (i)~\file{plot\_descent.py}
— is $J$ actually decreasing, or is the step being rejected? (ii)~\file{plot\_gradient\_map.py}
— is the gradient zero over the area to be reconstructed? In the latter case the parameter
is not observable over the chosen window: it is the \emph{window} that must be fixed
(see \file{identifiability\_plot.py}), not the optimiser.
\end{tcolorbox}

\section*{Minimal recipe (summary)}
% =====================================================================
\begin{lstlisting}[language=bash]
# 0. build once
export ENZYME_PLUGIN_DIR=$HOME/Enzyme/build/Enzyme
cmake -S assim -B build_assim -DENABLE_ENZYME=ON -DCMAKE_CXX_COMPILER=clang++-18
cmake --build build_assim -j

# 1. references (twin experiment)   2. validate the gradient   3. assimilate
build_assim/sw2d_enzyme my_case gen-ref-e
build_assim/sw2d_enzyme my_case taylor
build_assim/sw2d_enzyme my_case minimize
# -> result : my_case/optimized_porosity.txt

# 4. diagnose
python3 utils_assim/python/plot/plot_descent.py my_case/descent/descent_log.csv
\end{lstlisting}
